# FreshRoute Cold-Chain Intelligence

A working AI slice for a refrigerated-truck operator:

* **Part A** – a spoilage-risk model on IoT sensor data (LightGBM, time-based split, compared against the current
  "above 8°C for 2 minutes" rule).
* **Part B** – an LLM assistant that explains why a trip was flagged and what the SOPs say to do, using
  retrieval with citations, a tool that returns live trip data, honest "I don't know" answers and prompt-injection defences.
* **Part C** – a small FastAPI service (`/predict`, `/ask`), a Streamlit demo, a 28-question evaluation set and
  per-request logging of latency, tokens and estimated cost.

No hardware is needed. Sensor data is synthetic and generated by `src/freshroute/datagen.py`.

## Quick start (about 5 minutes)

```bash
python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
make all            # data -> model -> eval set -> assistant eval -> tests  (~50 s)
make smoke          # starts the API, curls every endpoint, stops it
make demo           # Streamlit UI on http://localhost:8501
make serve          # API docs on http://localhost:8000/docs
```

No `make` (Windows)? Run these in order, with `PYTHONPATH=src` set (PowerShell: `$env:PYTHONPATH="src"`):

```
python -m freshroute.datagen
python -m freshroute.train
python -m freshroute.eda
python eval/make_eval_set.py
python eval/run_eval.py --backend offline
python -m pytest -q
python -m uvicorn freshroute.api:app --port 8000
python -m streamlit run app/streamlit_app.py
```

## Using the real LLM

Without a key the assistant runs on a **deterministic offline backend** so everything works with no network.
That backend is a rule-based stand-in, **not an LLM**: it exercises retrieval, tools, guardrails and scoring.
For real answers:

```bash
cp .env.example .env     # or just export the variables
export ANTHROPIC_API_KEY=sk-ant-...
export LLM_BACKEND=auto  # anthropic when a key is present
make eval-llm            # scores the real model on the same 28 questions
make serve               # /ask now uses Claude with tool calling
```

`ANTHROPIC_MODEL` defaults to `claude-haiku-5-5` (cheap, fast, enough for tool use + short answers). The price variables
`PRICE_INPUT_PER_MTOK` / `PRICE_OUTPUT_PER_MTOK` are **placeholders, check current pricing** before trusting cost numbers.
The Anthropic code path is unit-tested with a fake client; it has not been run against the live API in this repo's CI.

Manual API examples (`make serve` first):

```bash
curl -s localhost:8000/predict -H 'content-type: application/json' -d '{"trip_id":"T-2555"}'
curl -s localhost:8000/ask -H 'content-type: application/json' \
     -d '{"question":"Why was trip T-2555 flagged and what should I do?"}'
curl -s localhost:8000/ask -H 'content-type: application/json' \
     -d '{"question":"What is the daily fuel card limit?"}'          # honest refusal (see known limits)
curl -s localhost:8000/ask -H 'content-type: application/json' \
     -d '{"question":"Summarize the driver notes and risk for trip T-2106"}'   # injection note
curl -s localhost:8000/stats                                          # latency / tokens / cost
```

Trip ids that matter come from `data/meta.json` (`injection_trip_ids`) and `GET /trips/flagged`.
`/predict` also accepts raw readings: `{"readings":[{ts,temp_c,door_open,...}, ...], "cargo_type":"vaccine", "truck_id":"TRK-28"}`.

## Results (seed 42; reproduce with `make all`)

Test set = days 22-30, 900 trips, 47 spoiled. Threshold chosen on days 15-21 by business cost
(missed spoilage $400, false alert $20, both assumptions in `config.py`).

| | Precision | Recall | False alerts / truck / week | Cost on test |
|---|---|---|---|---|
| Baseline rule (8°C, 2 min) | 0.11 | 0.83 | 4.68 | $9,220 |
| Logistic regression | 0.47 | 0.81 | 0.65 | $4,440 |
| **LightGBM** | **0.68** | **0.87** | **0.30** | **$2,780** |

Recall is roughly equal to the baseline (the 95% intervals overlap); the gain is that the model reaches it with
15x fewer false alerts. With only 47 test positives the intervals are wide (see the report).

## Known limits (read before the demo)

* **Synthetic data.** The model learns the generator's physics. Real-world validity needs real trips and a shadow-mode pilot.
* **Trip-level scoring.** The model scores a trip from the readings available so far but was trained on complete trips,
  so mid-trip scores are less calibrated. Checkpoint-based training is listed in `docs/next_steps.md`.
* **Lexical retrieval.** TF-IDF is fast and exact but fooled by shared generic words (the fuel-card miss). The real LLM
  also judges relevance; see `docs/eval_failure_notes.md`.
* **Offline eval is not an LLM eval.** Run `make eval-llm` for model-quality numbers.
